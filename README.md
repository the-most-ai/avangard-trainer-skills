# AvangardAI Trainer Skills

Библиотека **навыков (skills)** для голосового тренажёра диалогов AvangardAI.
Формат — открытый стандарт Agent Skills (`SKILL.md`), совместимый с Codex/OpenAI,
Claude Code и др. Каждый навык запускает репетицию разговора: пользователь
**говорит вслух** с ИИ-собеседником и получает оценку по критериям.

## Модель (важно про содержимое)

Здесь лежит только **тонкий внешний слой**: имена сценариев (id), «когда звать»,
схема параметров. Сами персоны — их характер, скрытые мотивы, критерии оценки —
**живут на бэкенде AvangardAI** и резолвятся по id сценария. В этом репозитории их нет
и быть не должно: это граница, за которую контент не отдаётся.

## Что внутри

- `.agents/skills/` — 8 навыков по доменам (57 сценариев суммарно):
  продажи, поддержка, финансы, закупки, менеджмент, HR, софт-скиллы, ресёрч.
  Каждый навык:
  - `SKILL.md` — `name` + `description` (когда активировать) + инструкции;
  - `agents/openai.yaml` — зависимость от MCP-инструмента `create_training_profile`
    и политика вызова;
  - `references/scenarios.md` — таблица сценариев (id, «когда звать», роли, схема `params`).
- `scripts/smoke.py` — структурная самопроверка репозитория.

## Два пака и как они связаны

Тренажёр для пользователей Яндекса — это **два пакета**:

1. **MCP AvangardAI** — MCP-сервер тренажёра (инструмент
   `create_training_profile`). Это исполняющий слой: он резолвит id сценария
   в персону на бэкенде и поднимает голосовую сессию.
2. **Пак навыков (этот репозиторий)** — тонкий слой поверх MCP: 8 навыков с
   предустановленными кейсами-алиасами. Навыки не содержат контента, они лишь
   маршрутизируют ситуацию пользователя в нужный id сценария и вызывают MCP.

**MCP подтягивается вместе с навыком.** Каждый `agents/openai.yaml` объявляет
MCP как зависимость (`dependencies.tools`, `type: "mcp"`). Это штатный механизм
Codex «tool dependencies»: когда пользователь ставит навык из библиотеки скиллов,
вместе с ним подтягивается и MCP-сервер тренажёра — отдельно его подключать не
нужно. Если MCP уже подключён, зависимость просто ссылается
на него.

> Координаты MCP тренажёра AvangardAI:
> - `value` (имя сервера) — `most-trainer`
> - `url` — `https://api-trainer.avangardai.ru/mcp`
> - `transport` — `streamable_http`
>
> **Авторизация — вне репозитория.** Сервер ждёт заголовки `X-Partner-Key`
> (партнёрский ключ) и `X-User-Hash` (идентификатор пользователя). Ключи в этот
> репозиторий **не зашиваются** — каждый партнёр получает свой ключ и задаёт его
> в конфиге MCP на своей стороне (через env). В навыках нет и
> не должно быть ни одного секрета.

## Установка

1. Скопируйте папку `.agents/skills/` в корень вашего проекта (Codex сканирует
   `.agents/skills/` вверх по дереву) **или** отдельные навыки в `~/.codex/skills/`.
2. Проверьте `agents/openai.yaml` каждого навыка — что `value`/`url` указывают на
   ваш подключённый MCP AvangardAI.
3. Перезапустите сессию агента — навыки подхватятся по `name`/`description`.

## Как инициировать

- **Неявно:** опишите ситуацию («надо отрепетировать жёсткий отказ клиента по цене»)
  — агент сам выберет навык по `description` и вызовет `create_training_profile`.
- **Явно:** `$avangard-sales-training` — форсировать конкретный навык.

Навык выбирает подходящий id сценария и вызывает:

```
create_training_profile(
    scenario = "client.objection",     # id из references/scenarios.md
    difficulty = "medium",             # easy | medium | hard (опц.)
    params = { "industry": "...", "product": "...", "situation": "..." }  # опц. контекст
)
```

В ответе — ссылка на голосовую тренировку; агент отдаёт её пользователю.

## Проверка, что всё работает (verify)

1. `python3 scripts/smoke.py` — структурная проверка: все `SKILL.md` валидны,
   `agents/openai.yaml` парсится, каждый навык ссылается на MCP-инструмент,
   id сценариев уникальны. Должно быть `OK`.
2. Поставьте навыки, перезапустите агента, вызовите неявно фразой из «когда звать».
3. Убедитесь, что агент вызвал `create_training_profile` с корректным `scenario`,
   вернулась ссылка, и по ссылке поднимается голосовая сессия с собеседником в характере.

## params

`params` — свободный контекст ЭТОГО прогона (отрасль, продукт, суммы, имена, тон).
Накладывается на персону как **ДАННЫЕ** для реалистичности. НЕ меняет прибитые
критерии оценки, не персистится, не влияет на выбор персоны и её профиль.
